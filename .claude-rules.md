## 🏗️ ARQUITECTURA DEL PROYECTO

### Tipo de Arquitectura
**Clean Architecture con CQRS Pattern**

### Framework
- **.NET 8.0**
- **ASP.NET Core Web API**
- **Entity Framework Core 9.0.4**

### Principios SOLID Aplicados
- ✅ Single Responsibility Principle (SRP)
- ✅ Open/Closed Principle (OCP)
- ✅ Liskov Substitution Principle (LSP)
- ✅ Interface Segregation Principle (ISP)
- ✅ Dependency Inversion Principle (DIP)

### Separación de Responsabilidades
```
┌─────────────────────────────────────────────┐
│           Reserva.Api (Controllers)         │ ← Capa de Presentación
├─────────────────────────────────────────────┤
│      Reserva.Application (Services)         │ ← Capa de Aplicación
├─────────────────────────────────────────────┤
│   Reserva.Domain (Commands & Queries)       │ ← Capa de Dominio (CQRS)
├─────────────────────────────────────────────┤
│   Reserva.Repository (Data Access)          │ ← Capa de Infraestructura
```


**Ejemplo de Handler**: `CreateCanchaCommandHandler.cs`
```csharp
public class CreateCanchaCommandHandler : CommandHandlerBase<CreateCanchaCommand, GetCanchaDto>
{
    private readonly IRepository<Entity.Cancha> _CanchaRepository;

    public CreateCanchaCommandHandler(
        IUnitOfWork unitOfWork,
        IMapper mapper,
        IMediator mediator,
        CreateCanchaCommandValidator validator,
        IRepository<Entity.Cancha> CanchaRepository
    ) : base(unitOfWork, mapper, mediator, validator)
    {
        _CanchaRepository = CanchaRepository;
    }

    public override async Task<ResponseDto<GetCanchaDto>> HandleCommand(
        CreateCanchaCommand request,
        CancellationToken cancellationToken
    )
    {
        var response = new ResponseDto<GetCanchaDto>();

        // 1. Mapear DTO a Entidad
        var Cancha = _mapper?.Map<Entity.Cancha>(request.CreateDto);

        // 2. Aplicar lógica de negocio
        Cancha!.IdEstadoCancha = estadoDefault.IdEstadoCancha;

        // 3. Guardar en BD
        await _CanchaRepository.AddAsync(Cancha);
        await _CanchaRepository.SaveAsync();

        // 4. Mapear resultado y retornar
        var CanchaDto = _mapper?.Map<GetCanchaDto>(Cancha);
        response.UpdateData(CanchaDto);
        response.AddOkResult(Resources.Common.CreateSuccessMessage);

        return response;
    }
}
```

**Validador**: `CreateCanchaCommandValidator.cs`

**Repository Genérico**: `Repository.cs`
```csharp
public class Repository<TEntity> : IRepository<TEntity> where TEntity : class
{
    protected readonly DbContext _dbContext;
    protected readonly IUserIdentity _userIdentity;

    public async Task<TEntity?> AddAsync(TEntity entity)
    {
        if (entity == null) return null;
        UpdateAuditTrails(entity);  // Auditoría automática
        await _dbContext.Set<TEntity>().AddAsync(entity);
        await _dbContext.SaveChangesAsync();
        return entity;
    }

    public async Task<SearchResult<TEntity>> SearchByAsync(
        int page,
        int pageSize,
        IEnumerable<SortExpression<TEntity>>? sortExpressions,
        Expression<Func<TEntity, bool>> filter
    )
    {
        // Implementación de búsqueda con paginación y ordenamiento
    }

    private void UpdateAuditInfo(object entity, bool creation = true)
    {
        var usuario = _userIdentity.GetCurrentUser();
        var now = DateTimeOffset.UtcNow;

        if (creation)
        {
            UpdateProperty(entity, properties, "UserNameCreate", usuario);
            UpdateProperty(entity, properties, "CreateDate", now);
            UpdateProperty(entity, properties, "Activo", true);
        }

        UpdateProperty(entity, properties, "UserNameUpdate", usuario);
        UpdateProperty(entity, properties, "UpdateDate", now);
```

**REGLA**:
- SIEMPRE usar `IRepository<TEntity>` para acceso a datos
- NUNCA acceder directamente a DbContext desde Domain o Application
- La auditoría se aplica AUTOMÁTICAMENTE en Add/Update

**Unit of Work**: `UnitOfWork.cs`
```csharp
public class UnitOfWork<TContext> : IUnitOfWork where TContext : DbContext
{
    private readonly TContext _dbContext;

    public async Task<TResult> ExecuteInTransactionAsync<TState, TResult>(
        TState state,
        Func<TState, CancellationToken, Task<TResult>> operation
    )
    {
        var executionStrategy = Context.Database.CreateExecutionStrategy();

        return await executionStrategy.ExecuteAsync(async () =>
        {
            using var transaction = await BeginTransactionAsync();
            try
            {
                var result = await operation.Invoke(state);
                await CommitAsync();
                return result;
            }
            catch
            {
                await transaction.RollbackAsync();
                throw;
            }
        });
    }
}
```

**REGLA**: Las transacciones se manejan AUTOMÁTICAMENTE por `CommandHandlerBase` si `UseTransaction = true`.

## 🎨 PATRONES DE DISEÑO IMPLEMENTADOS

### 1. **CQRS (Command Query Responsibility Segregation)**
- **Commands**: Modifican estado (Create, Update, Delete)
- **Queries**: Solo lectura (Get, List, Search)
- **Ubicación**: `Reserva.Domain/Commands` y `Reserva.Domain/Queries`

### 2. **Mediator Pattern (MediatR)**
- Desacopla controllers de handlers
- **Librería**: MediatR v12.5.0
- **Uso**: `await _mediator.Send(new CreateCanchaCommand(dto))`

### 3. **Repository Pattern**
- Abstrae acceso a datos
- **Genérico**: `IRepository<TEntity>`
- **Ubicación**: `Reserva.Repository/Base/Repository.cs`

### 4. **Unit of Work Pattern**
- Gestiona transacciones
- **Ubicación**: `Reserva.Repository/Transactions/UnitOfWork.cs`

### 5. **Dependency Injection**
- Inversión de control en toda la aplicación
- **Configuración**: `Program.cs`
- **Auto-registro**: Scrutor

### 6. **Strategy Pattern**
- Entity Framework Execution Strategy
- **Ubicación**: `UnitOfWork.ExecuteInTransactionAsync()`

### 7. **Template Method Pattern**
- `CommandHandlerBase` y `QueryHandlerBase`
- Define algoritmo base, subclases implementan pasos específicos

### 8. **Validation Pattern (FluentValidation)**
- Validaciones declarativas
- **Ubicación**: `Domain/Commands/Xxx/XxxValidator.cs`

### En CommandHandler
```csharp
public async Task<TResponse> Handle(TRequest request, CancellationToken cancellationToken)
{
    var attempts = 0;
    while (attempts < ConcurrencyAttempts)
    {
        try
        {
            return await HandleAttempt(request, cancellationToken);
        }
        catch (DbUpdateConcurrencyException)  // Reintentos automáticos
        {
            attempts++;
            if (ConcurrencyThrowException || attempts == ConcurrencyAttempts)
                throw;
            continue;
        }
        catch (ResultException<TResponse> rex)  // Resultado esperado
        {
            return rex.Result;
        }
        catch (Exception ex)  // Error inesperado
        {
            var errorResponse = await OnHandleError(ex);
            if (errorResponse != default(TResponse))
                return errorResponse;
            throw;
        }
    }
}
```

## 🚨 ERRORES COMUNES Y SOLUCIONES

### Error: "The instance of entity type cannot be tracked"
**Causa**: Intentar agregar/actualizar una entidad ya trackeada.
**Solución**: Usar `AsNoTracking()` en queries o limpiar ChangeTracker.

### Error: "A second operation was started on this context"
**Causa**: Operaciones concurrentes en el mismo DbContext.
**Solución**: Usar `await` correctamente y evitar paralelismo en el mismo contexto.

### Error: "Validation failed"
**Causa**: FluentValidation encontró errores.
**Solución**: Revisar los mensajes en `ResponseDto.Messages`.

### Error: "Sequence contains no elements"
**Causa**: Usar `.First()` en colección vacía.
**Solución**: Usar `.FirstOrDefault()` y validar null.

### Error: "Cannot insert explicit value for identity column"
**Causa**: Intentar insertar ID manualmente en columna IDENTITY.
**Solución**: No asignar valor a la clave primaria en Create.
